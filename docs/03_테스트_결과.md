## 4. 코드 리뷰 반영
Gemini에게 핵심 코드를 리뷰받아 다음을 반영했다. (Codex는 사용량 한도로 이용하지 못했다.)
| 지적 | 판단 | 조치 |
|---|---|---|
| MySQL 기본 격리(REPEATABLE READ)에서 잠금 전에 읽기 스냅샷이 만들어지면 포인트 이중 사용 가능 | 타당 (H2 시험으로는 드러나지 않음) | 회원 락을 트랜잭션 첫 문장으로 이동 + 격리 수준 READ COMMITTED |
| 원장 유니크 위반을 try/catch로 삼키면 rollback-only와 어긋남 | 타당 | 예외를 삼키지 않도록 제거(행 잠금이 중복을 막음) |
| 통계 UPSERT가 동시에 겹치면 PK 중복 | 타당(가능성 낮음) | 중복이면 다시 갱신 |
| `getTimestamp` 시각 변환 | 일부 타당 | `getObject(LocalDateTime)`로 변경 |
(리뷰는 지점 도입 전 코드에 대한 것이다. 지점·연장·키오스크 코드는 리뷰받지 않았다.)

## 5. 아직 확인하지 못한 것
- **MySQL 8 실제 서버**: 시험은 H2(MySQL 모드)에서만 돌렸다. 격리 수준·락 대기 동작은 MySQL에서 다시 확인해야 한다.
- **모바일 폭 화면**: 반응형 CSS(모바일 하단 탭, 도면 가로 스크롤)는 작성했지만 브라우저 창 폭이 바뀌지 않아 직접 확인하지 못했다.
- **새 화면의 권한·CSRF**: 위 3번의 괄호 설명처럼 새 화면에서는 다시 확인하지 않았다.
- **웹 계층 자동 시험 없음**: 컨트롤러·템플릿은 자동 시험이 아니라 실행 중인 앱에 대한 HTTP·브라우저 확인으로만 검증했다. (키오스크 CSRF 누락 같은 문제는 이런 시험이 있으면 막을 수 있었다.)
- **내 위치 가까운 순 정렬**: 브라우저 위치 권한이 필요해 직접 눌러 보지 못했다.
- **입실 성공 경로(앱 버튼·키오스크)**: 입실 가능 시간(시작 10분 전)에 맞춰 화면에서 성공까지 눌러 보지는 못했다. 서비스 규칙은 자동 시험으로 확인했고, 화면에서는 시작 전 거부 메시지만 확인했다.
- 장시간 가동 시 스케줄러(1분 점검·매시 집계)의 실제 반복 실행은 시각을 고정한 단위 시험으로만 확인했다.
- 브라우저 호환성은 Chrome에서만 봤다.
