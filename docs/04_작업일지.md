### 2차: "진짜 서비스처럼" 다시 만들기 (사용자 피드백: 너무 대충 만들었다)
- 국내 스터디카페 앱 소개·고객센터 문서를 조사해 공통 기능을 정리: 위치 기반 지점 탐색·내 지점, 실시간 좌석 현황, 요금 체계, 연장, QR 입퇴실, 충전·마일리지, 지점별 운영 시간
- DB 확장(V3·V4): 지점·구역 가격·좌석 도면 좌표·도면 장식·내 지점·예약 코드. 5개 가상 지점 도면은 `tools/gen_branches.py`로 생성
- 서비스: 구역 가격·지점 운영 시간 반영 예약, 연장(예약당 1회, EXTEND 원장), 키오스크 입·퇴실(코드), 충전 패키지·보너스, 지점 목록·상세·도면 상태 계산, 통계 집계를 지점 운영 시간 기준으로 변경
- 화면 전면 재작성: 지도(Leaflet/OSM)+지점 카드, 지점 상세, 날짜·시간 선택 + 도면 좌석 선택, 예약 상세(QR), 내 예약, 포인트 충전, 키오스크, 관리자 대시보드
- 시험 22개로 확장(연장·키오스크·24시간 지점·구역 가격·지점 목록·도면 상태·내 지점·충전) → 이후 전국 분포 시험 추가로 30개
- 실행해서 직접 확인하며 발견·수정한 문제: 
  - 구역 이름 유니크 제약이 지점마다 같은 이름("일반석")을 막음 → 지점 안에서만 유니크로 변경
  - 이름이 대문자 한 글자로 끝나는 필드(`planH`, `posX`)가 컬럼명 매핑 실패 → `@Column` 명시
  - 비로그인 사용자의 도면 페이지에서 CSRF 토큰 때문에 응답 뒤 세션 생성 오류 → 비로그인에는 예약 폼을 렌더링하지 않음
  - 홍대점 부스·건대 라운지 좌석 겹침 → 생성기에 겹침 검사 + 배치 수정
  - 키오스크 폼에 CSRF 토큰 누락 → `th:action` 부여
- "서울만 나온다 · 너무 적다 · 주변은 다 도시 아니냐 · 진짜 있는 지역으로, 없어진 곳은 빼고" 지적 → 먼저 실제 현황 조사(전국 가맹점 6,944곳, 2024.10) → 최신(2026.10) 행정동 데이터로 256개 시·군·구·3,559개 읍·면·동 중 실제 구역에만 지점 배치(전남·광주 통합 반영), 모든 시·군·구에 최소 1곳·읍면에도 드물게, 대전은 61곳(표본 지역). 사용자가 "너무 많이까지는 안 해도 된다"고 해서 약 10% 규모(722곳)로 제한
  - 규모가 커져 지도 홈을 서버 렌더링에서 JSON API + 화면 렌더링으로 바꾸고(시·도 칩, 시·군·구 선택, 더 보기), 지점 목록은 SQL 집계 한 번 + 20초 캐시, 통계 집계·보충은 SQL 집합 연산, 데모 데이터는 JDBC 배치, 관리자 화면은 시·도 요약 + 연쇄 선택 + 지점 검색으로 변경
  - 후기 작성자가 전부 "방*"으로 같던 문제 → 서로 다른 작성자 12명, 이름 가림을 `김*우` 형식으로 변경
  - 시험 30개로 확장(전국 분포 규칙·도면 템플릿·저장 결과)

- 좌석 선택 화면 사진 3장(독서실·스터디카페 앱)을 받고 "제대로 볼 수 있게" 요청 → 도면을 실제 서비스처럼: 칸막이·의자 책상, 문 있는 스터디룸, 키오스크·사물함, 여성/남성 전용·고정석·퇴실예정석, 범례. 규칙은 도면과 서버 양쪽에 적용(V5 마이그레이션, 성별 가입 항목), 시험 35개로 확장
  - 일반 좌석 수가 줄어(성별 전용·고정석 제외 4석) 기존 시험이 모자라 시험을 일반 좌석 기준으로 수정, 시간권 좌석 수에서 고정석을 빼는 정의 변경

- 좌석 화면에 대해 "형태가 너무 짜치다, 사진(작심)처럼 구도 있게" 재요청 → 격자 템플릿을 버리고 도면 엔진(`FloorPlanLayout`)으로 교체: 바깥 벽·문 있는 방·스터디존/카페존 책상 섬·사물함·서비스바·키오스크·입구·테이블, 4스타일. 기존 38개 지점은 앱 시작 때 좌석 속성은 그대로 두고 재배치(V6 `layout_ver`). 시험 40개
  - 시험이 겹침을 756가지 조합에서 확인하고, 화면에서 구역 이름표 겹침을 발견해 칩으로 이동
